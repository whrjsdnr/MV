# 승인된 제품 GT 재사용 Crop 후보

하늘색(청록) 박스는 사용자가 이미 승인한 제품 전체 BBox다. 새 자동 탐지 결과가 아니다. 이 600개를 제품 범위 기준으로 재사용해 Crop 후보와 보존 점검을 자동 계산했다.

| 항목 | 실제 결과 |
|---|---:|
| 재사용한 승인 제품 BBox | 600장 |
| 후보 안에 제품 BBox 완전 포함 | 600장 |
| 제공된 양성 결함 마스크 | 199장 |
| 관측 결함 마스크 손실 | 0장 |
| 마스크 미제공 | 401장, 마스크 평가는 NA |
| 평균 Crop 한 변 | 889.565px |
| 평균 기하 확대율 | 1.165474배 |
| 원본 전체가 된 후보 | 87장, 14.5% |

401장에는 정상 이미지도 포함되며 전부 NG 미제공으로 해석하면 안 된다. 마스크가 없는 경우에도 제품 BBox 포함 여부는 확인했지만 결함 픽셀 보존을 계산한 것처럼 보고하지 않는다.

BBox 각 변에 너비·높이의10% 여백을 추가하고 정사각형으로 확장한다. 기존 `square_crop()`의 정수화 보호2px와 프레임 안쪽 이동 규칙을 그대로 사용했다. Python과 웹 JavaScript의600개 결과가 모두 일치했다.

- [600개 Crop 후보 CSV](../outputs/adaptive_crop_full_v1/gt_reference_crop_candidates.csv)
- [재사용 결과 JSON](../outputs/adaptive_crop_full_v1/gt_reference_crop_reuse_summary.json)
- [JS/Python 좌표 일치 검증](../outputs/adaptive_crop_full_v1/gt_crop_js_python_parity.json)

검수 목록1,757장 중 하늘색 제품 GT 참조가 있는 항목은173장이다. 웹페이지를 새로 불러오면 미승인 GT 항목에 대해 GT+10% 후보를 불러오고 보존 점검을 자동 실행한다. 기존 수동 Crop 승인 항목은 해당 승인 범위를 유지한다. 편집 중인 범위가 있으면 저장 후 새로고침한다.

다음으로 이동하는 동작은 새 Crop 승인·저장이 아니다. 실제 전처리에 반영하려면 Crop 승인과 새 CSV 내보내기가 필요하다. 제품 GT와 수동 Crop 이력을 분리하고, 자동 점검을 사람이 새로 승인한 것으로 기록하지 않았다.

이 후보는 정답 보조 방식이다. Test GT를 참조한 후보를 정답을 사용하지 않는 자동 전처리 성능으로 주장할 수 없다. 기존 전수 `preprocessing_metadata.csv`는 원본 유지 기준을 그대로 보존한다. 새 모델 학습·가중치 다운로드·Crop 이미지 파일 생성·GitHub Push는 수행하지 않았다.
